# UX-00 — Princípios de UX

**Versão:** 1.0  
**Status:** Draft  
**Documento:** UX-00_UX_PRINCIPLES.md

---

# 1. Objetivo

Este documento estabelece os princípios de Experiência do Usuário (UX) para o BORAH. Seu propósito é garantir que todas as funcionalidades, telas e fluxos mantenham uma experiência consistente, intuitiva, acessível e divertida, alinhada ao propósito do produto: transformar saídas para restaurantes em experiências sociais memoráveis.

---

# 2. Objetivos da Experiência

A experiência do BORAH deve:

- Incentivar encontros presenciais.
- Tornar a organização de saídas simples.
- Reduzir o número de passos para concluir tarefas.
- Estimular o engajamento por meio da gamificação.
- Fortalecer a interação entre amigos.
- Ser agradável para novos usuários e usuários recorrentes.

---

# 3. Personas

## Persona 1 — Organizador
- Cria grupos.
- Agenda eventos.
- Define restaurantes.
- Busca praticidade.

## Persona 2 — Participante
- Recebe convites.
- Confirma presença.
- Avalia restaurantes.
- Acompanha rankings.

## Persona 3 — Explorador
- Descobre novos restaurantes.
- Gosta de colecionar badges.
- Busca desafios e conquistas.

---

# 4. Princípios de UX

## Simplicidade
A interface deve minimizar a carga cognitiva.

## Rapidez
As tarefas mais frequentes devem exigir o menor número possível de ações.

## Clareza
Cada tela deve ter um objetivo principal e uma hierarquia visual evidente.

## Consistência
Padrões de navegação, cores, componentes e nomenclaturas devem ser reutilizados em todo o aplicativo.

## Feedback
Toda ação do usuário deve gerar uma resposta visual imediata.

## Diversão
A gamificação deve incentivar o uso sem prejudicar a usabilidade.

---

# 5. Jornada do Usuário

1. Instalar o aplicativo.
2. Criar conta ou entrar.
3. Completar o perfil.
4. Entrar ou criar um grupo.
5. Organizar um evento.
6. Escolher um restaurante.
7. Participar do encontro.
8. Realizar check-in.
9. Avaliar a experiência.
10. Evoluir no ranking e conquistar badges.

---

# 6. Navegação

- Barra inferior para funcionalidades principais.
- Navegação consistente entre telas.
- Botão de retorno previsível.
- Fluxos curtos e objetivos.

---

# 7. Microinterações

Aplicar microinterações para:

- Curtidas.
- Confirmação de presença.
- Check-in.
- Conquista de badges.
- Evolução de nível.
- Atualização de ranking.

---

# 8. Estados de Interface

Cada tela deverá prever:

- Carregando (Loading)
- Vazio (Empty State)
- Erro
- Sem conexão
- Sucesso

---

# 9. Acessibilidade

- Contraste adequado.
- Fontes legíveis.
- Áreas de toque mínimas de 48x48 px.
- Compatibilidade com leitores de tela.
- Navegação sem depender exclusivamente de cores.

---

# 10. Escrita (UX Writing)

As mensagens devem ser:

- Claras.
- Objetivas.
- Humanizadas.
- Positivas.
- Sem jargões técnicos.

Exemplo:

❌ "Erro 500"

✅ "Não foi possível carregar as informações. Tente novamente."

---

# 11. Performance Percebida

- Exibir skeletons durante carregamento.
- Evitar telas em branco.
- Utilizar animações curtas (<300 ms).
- Priorizar conteúdo principal.

---

# 12. Métricas de UX

Indicadores recomendados:

- Tempo para criar um evento.
- Tempo para confirmar presença.
- Taxa de conclusão do cadastro.
- Retenção de usuários.
- Eventos realizados por grupo.
- Avaliações concluídas.

---

# 13. Boas Práticas

- Não esconder ações importantes.
- Evitar excesso de modais.
- Priorizar componentes reutilizáveis.
- Reduzir formulários longos.
- Confirmar ações destrutivas.

---

# 14. Critérios de Aceite

- Fluxos intuitivos.
- Consistência visual.
- Navegação previsível.
- Acessibilidade considerada.
- Estados de interface definidos.
- Feedback visual em todas as ações.

---

# 15. Checklist

- Objetivos de UX documentados.
- Personas definidas.
- Jornada validada.
- Princípios estabelecidos.
- Regras de acessibilidade registradas.
- Diretrizes de UX Writing documentadas.
- Métricas definidas.
